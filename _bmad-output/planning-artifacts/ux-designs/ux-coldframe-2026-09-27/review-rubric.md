# Spine Pair Review — Coldframe

## Overall verdict
The pair is a usable contract. Every colour token has a hex value and light/dark pairs, every `{path}` reference resolves, all five spec journeys have a Key Flow with a protagonist and a climax, and the Lot-status and stale-data rules are specified well enough to build from without guessing. Most of the gaps are at the seams. Several components are specified in only one spine, or under different names in each. `DESIGN.md` still describes direction B's live-BLE calibration panel, which the memlog dropped in favour of stored-Reading calibration. Sign-in errors, notification-permission denial and calibration failures have no specified states. No criticals; five highs should be fixed before epics are cut from these spines.

## 1. Flow coverage — adequate
Checked: UJ-1…UJ-5 from `specs/spec-coldframe/user-journeys.md`, UJ-6 (added in UX), and the CAP-1…21 intents in `SPEC.md`. All six have a named protagonist, numbered steps and a bold **Climax** beat. UJ-1, UJ-5 have failure paths. UJ-2 has an edge case and UJ-3 a variant. UJ-4 and UJ-6 have neither.

### Findings
- **medium** CAP-10 (set/change/remove Thresholds) has no Key Flow. UJ-2 relies on "your low is 30 %", but no flow shows the Thresholds screen being reached, the default proposal (Min + 20 % × range) or saving. First-run step tile 4 "Set a low Threshold" has no flow (EXPERIENCE.md §Key Flows UJ-1 ends at the Notification Window, step 9). *Fix:* add a step to UJ-1 after the Calibration climax (Thresholds opened from the confirmation, proposed low accepted, Save), or add a short flow.
- **medium** UJ-4 has no failure or edge path: a Member trying to pause, a Device added while the Site is paused ("start paused", CAP-18), an automatic resume at the end date. Step 1 also allows "Until left empty (or 1 Mar)", but the step 3 climax only shows "Paused until 1 Mar" (EXPERIENCE.md §UJ-4). *Fix:* pick one example path and add an edge line for the automatic end-date resume.
- **medium** UJ-6 has no failure path, although it covers the most rejection-prone admin actions: removing a Lot that holds a Node, demoting the last Owner, moving a Node onto an occupied Lot (EXPERIENCE.md §UJ-6). *Fix:* add a "Failure:" line that points to the existing validation copy in State Patterns.
- **low** CAP-14 (low battery), CAP-17 (mute) and CAP-9 recalibration ("changes only new Readings") appear only in component rows and notification payloads, with no flow. Acceptable for V1, but recalibration from Lot detail is an unflowed path (EXPERIENCE.md §Component Patterns "Calibration reference point"). *Fix:* optional one-line variant under UJ-1.
- **low** UJ-1 step 7 relies on the Node setup-button "report now", which is tagged `[ASSUMPTION]` pending the Node epic. The main path should read correctly without it (EXPERIENCE.md §UJ-1 step 7). *Fix:* write the step as "waits for the next Reading (≤ 15 min)" and treat the button as an optional shortcut.
- **low** UJ-5 step 2 says "the app opens on Home's overview", but IA gives Accept invitation as web-only `[ASSUMPTION]` (EXPERIENCE.md §IA row "Accept invitation" vs §UJ-5). *Fix:* say "the web app opens…" or resolve the assumption.

## 2. Token completeness — adequate
Checked: 77 colour tokens, 14 typography roles, rounded, 21 spacing tokens and 38 component token groups in DESIGN.md frontmatter, plus every `{path.to.token}` reference in both spines (script-verified: 0 unresolved). All colours have hex values. The rule "tokens without a `-dark` twin are identical in both themes" is stated (DESIGN.md L12) and holds on inspection. Typography gives literal base sizes with platform scaling notes. Contrast targets are stated for tile text and non-text borders.

### Findings
- **high** The `calibration-live-value` token group uses `steady: {colors.support-success}` (`#48CF00`) as **text** ("steady for 5 s, ready to record") on `layer-01` `#F4F4F4`. That is about 1.9:1 in the light theme, well below 4.5:1 (DESIGN.md L343–346, L456). See also §3: the component itself is obsolete. *Fix:* remove the token group together with the component. If a "fresh Reading arrived" text colour is still needed, use a text-safe token (e.g. `text-primary`, plus a Carbon checkmark icon).
- **medium** `confirm-panel.border` uses `{colors.support-warning}` `#FFCB0F` on a light `background` `#FEFEFE`, about 1.4:1 non-text, under 3:1. DESIGN.md Colors itself says "yellow-500 is illegible on white" and uses yellow-700/800 for the light theme, but this component does not follow its own rule (DESIGN.md L357, L402). *Fix:* point it to `{colors.status-calibration-border}` / `-dark`, or add a `confirm-border` light/dark pair.
- **medium** `outcome-screen-error.eyebrow` uses `{colors.support-error}` `#FF454B` as small uppercase text on `#FEFEFE`, about 3.3:1, below 4.5:1 (DESIGN.md L372, L462). *Fix:* add a light-theme `support-error-text` token (DS red-600/700) with a dark twin.
- **medium** `button-primary` uses white `text-on-color` on orange, about 2.7:1. It is declared DS-owned `[ASSUMPTION]`, but `segmented-choice` and `first-run-step-tile` put `ink-on-bright` on the same orange. So the most frequent CTA is the one orange surface that fails 4.5:1, and the two treatments conflict (DESIGN.md L296, L322, L365, L399). *Fix:* either accept the DS button contrast explicitly as a recorded exception in the Accessibility Floor, or use `ink-on-bright` on the button label as well.
- **low** Stated contrast figures are optimistic: `#0A0A0A` on `#FF770F` computes to about 7.4:1, not "8.2:1" or "≈ 8:1" (DESIGN.md L399, L407). *Fix:* correct the figures. The pass/fail result is unchanged.
- **low** `primary-hover` has a `-dark` twin, `primary-active` does not. Hover and active will diverge in the dark theme (DESIGN.md L38–40). *Fix:* add `primary-active-dark` or say that it is intentionally shared.
- **low** Unreferenced tokens: `layer-02`/`-dark`, `support-info`, `typography.tile-name` (named in prose without braces), `body-lg`, `spacing.tile-padding-web`, `rounded.DEFAULT`. *Fix:* reference `tile-name` and `tile-padding-web` as `{…}` in Layout & Spacing / Components; keep or drop the rest.

## 3. Component coverage — thin
Checked: 24 DESIGN.md Components entries (plus the `app-header-web` token group) against 27 EXPERIENCE.md Component Patterns rows, plus components named in IA, State Patterns and Key Flows.

### Findings
- **high** DESIGN.md "Calibration live value" ("LIVE RAW VALUE", "steady for 5 s, ready to record", citing B-plots-4/5) specifies the **live-BLE** calibration that the memlog dropped (memlog L27: "B's live-BLE calibration dropped"). EXPERIENCE.md specifies "Calibration reference point" on stored Readings: waiting state, last raw value with time, a list of recent Readings to pick from. The two spines describe incompatible screens, and there is no visual spec for the waiting state, the recent-Readings list or the "~% ±5 %" confirmation (DESIGN.md L343–346, L456; EXPERIENCE.md L97). *Fix:* replace the DESIGN component with "Calibration reference point": waiting panel (last raw + time, "Waiting for the next Reading"), selectable recent-Reading rows, and the confirmation block. Drop the "steady" semantics.
- **high** Surfaces central to navigation have no visual spec in DESIGN.md: **Devices list / Device row** (a main tab, with row actions and a swipe reveal), **Site menu** (the entry point for Site Pause/Resume in UJ-4), and **Site switcher** (an IA surface). Site menu and Site switcher also have no behavioural row in EXPERIENCE.md (IA L35, L42; §UJ-4 step 1; §Component Patterns L90). *Fix:* add DESIGN entries for Device row (Hub vs Node, silent and paused treatments), and add a Site menu / Site switcher row to both spines, covering the mobile sheet and the web AppHeader Site tabs.
- **medium** Behavioural-only components with no DESIGN visual spec: **Setup code field** (including the "accepted" chip), **Pause sheet**, **Invite form**, **Mute toggle** (native, acceptable), **Theme switcher** (covered implicitly by Segmented choice), **skeleton tile** (cold start, State Patterns L129). *Fix:* add one-line DESIGN entries for the setup-code chip, Pause sheet chrome and skeleton tile. The rest can point to DS/native.
- **medium** Visual-only components with no EXPERIENCE behavioural row: **First-run step tiles** (What does a Member see on an empty Site? Do completed steps disappear?), **Outcome screens** (only covered indirectly by the BLE error table), **Sign-in surface** (field validation, Keycloak hand-off, return), **Buttons**, **Text input**, **Navigation** (the Alerts count badge rule is only in IA prose). *Fix:* add rows for First-run step tiles, Sign-in surface and Outcome screens at minimum.
- **medium** The two spines name the same components differently: "Alert rows" / "Alert row"; "Confirm panel" / "Time-zone confirm panel"; "Selectable tile" / "Device candidate tile" + "Lot picker"; "Step counter + setup progress" / "Setup flow shell" + "Setup progress"; "Notification Window bar" / "Notification Window control"; "Calibration live value" / "Calibration reference point". *Fix:* use one canonical name per component in both files and in the frontmatter keys. Where one visual serves several behaviours, say so in the DESIGN entry (e.g. "Selectable tile — used by Device candidate tile and Lot picker").
- **low** "Setup flow shell" applies "NN / 05" to Calibrate, but Calibrate has two steps (dry and wet, B16 "STEP 1 OF 2") (EXPERIENCE.md L91). *Fix:* state the step count per flow.

## 4. State coverage — adequate
Checked every IA surface for empty, cold-load, loading, error, offline/stale, permission-denied and role-gated states. The overview, Lot detail (per status), Alerts, BLE setup errors, stale/unreachable and Member read-only are well covered.

### Findings
- **high** **Sign in** has no error states: Server address unreachable or mistyped, TLS/certificate failure (NFR-10, AD-13 real domain), not on the home network (NFR-1), Keycloak cancelled or failed, signed in but token expired later (EXPERIENCE.md §IA "Sign in"; §State Patterns has no rows). Every user hits this surface first, and it is the most likely place to fail when away from home. *Fix:* add a "Sign-in and session" block to State Patterns with copy per case, in the style of the BLE table.
- **high** **Notification permission denied or revoked** (iOS/Android OS permission, browser permission) is not handled. Coldframe's whole value is the notification, and a denied permission makes the product silently useless, which contradicts "silence never looks fine" (EXPERIENCE.md §Notifications "Permission"; §State Patterns). *Fix:* add a state for My notifications and a persistent inline notice on the overview: "Notifications are off for Coldframe on this phone — you won't get Alerts." with Open Settings.
- **medium** **Calibrate** failure states are missing: no Reading arrives (Node silent during calibration), the wet raw value is too close to or on the wrong side of the dry value, the flow is resumed after the Node was moved (EXPERIENCE.md L97). *Fix:* add rows (timeout copy after e.g. 20 min pointing to the Silent Node state; a validation message for "dry and wet are too close").
- **medium** **Accept invitation** covers only the off-network case. Invitation expired or revoked, already a Member, and signed in with a different account than the invited email are not specified (EXPERIENCE.md §UJ-5 Failure). *Fix:* add rows.
- **low** Missing empty or cold-load states: Devices with no Devices (Member on a new Site), Lot detail and Alerts cold load, Site switcher with a single Site, Members with only yourself, invite email send failure (SMTP). *Fix:* one row each, or a general cold-load rule that applies to every surface.
- **low** The Lot detail chart for a newly added Node (< 30 days) is only implied by "Days without Readings are gaps" (EXPERIENCE.md L86). *Fix:* state that the chart shows the days so far and gives no "no data" warning for days before the Node existed.

B-plots-3 shows an "ALREADY SET UP" Hub tile that the spine forbids (AD-25). Similar per-screen overrides already appear in the IA and memlog.

Key Flows and Component Patterns never point to the frame that illustrates them (e.g. UJ-1 → B-plots-3/4, Alerts → B-plots-2) (EXPERIENCE.md L19). *Fix:* add inline "→ B-plots-n (B09–B12)" pointers in the Key Flows.
- **low** The A and C captures are linked as bare numbers with no description of what each shows. This is acceptable because they are rejected, but it is unspecific (DESIGN.md L392). *Fix:* optional.

## 6. Bloat & overspecification — adequate
DESIGN.md prose is tight and every paragraph carries a decision. The editorial voice in Brand & Style is appropriate. EXPERIENCE.md is mostly tables.

### Findings

It says the Devices, Site settings, Site switcher, Appearance and browser notification surfaces have no journey and are "not invented further", yet UJ-6 now covers exactly those (EXPERIENCE.md L50 vs §UJ-6). *Fix:* delete the paragraph or replace it with "Covered by UJ-6 (UX-added; see §7)".
- **low** Foundation and Notifications restate architecture and spec content that consumers get from the source: the KMP path `packages/kt/core`, SignalR invalidation, AD-7 Server-side timing, the counter-metric (EXPERIENCE.md L15–17, L237, L256). *Fix:* reduce to one-line AD citations.
- **low** The "Calibration reference point" cell is a flow written as one paragraph inside a table cell (EXPERIENCE.md L97). *Fix:* move the step sequence to a Key Flow variant and keep only the rules in the row.

## 7. Inheritance discipline — adequate

### Findings

Orange is also used decoratively for the member-tile "you" initials, despite "never for decoration" (L362, L398). *Fix:* add the chart band to the green rule and change the member initials to neutral, or list both as exceptions.
